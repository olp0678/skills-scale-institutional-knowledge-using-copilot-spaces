# OctoAcme Project Management Docs

This guide brings together OctoAcme's project management processes, roles, and delivery practices. Use the linked documents for detailed checklists and templates; keep this index updated when process documents are added or renamed.

## Project management process summary

OctoAcme takes a customer-first, iterative approach based on clear ownership, data-informed decisions, and psychological safety. Projects move through initiation (validate the need, align stakeholders, and establish success measures), planning (prioritize and estimate work, define acceptance criteria and milestones, and identify risks and dependencies), execution and tracking (deliver in small increments, collaborate through a project board and pull requests, test quality, and monitor progress), release (deploy with verification and rollback plans), and retrospective and continuous improvement (capture learnings and track actionable improvements).

The Project Manager coordinates delivery, schedules, risks, and communications; the Product Manager/Product Lead defines outcomes, prioritizes work, and measures impact; developers design, build, and test; QA/testing validates quality and acceptance criteria; and stakeholders provide input and approvals. Regular team and stakeholder updates, shared project artifacts, and clear escalation paths support transparency throughout.

Quality is integrated into the workflow through acceptance criteria and a Definition of Done, CI tests and security scans, code review, relevant unit and integration testing, and smoke tests for critical flows. Releases are verified in staging and production, with rollback plans prepared. Retrospectives after sprints, releases, milestones, or incidents turn feedback into a small set of owned, trackable improvements.
